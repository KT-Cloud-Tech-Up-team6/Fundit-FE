## 문서 간 확인이 필요한 항목

- Auth·Member 보호 API의 Bearer 인증과 Gateway의 X-User-Id 주입·클라이언트 헤더 제거는 이번 YAML에 명시됐다. 이전 임시 X-Account-Id 방식을 FE 계약으로 채택하지 않는다. 실제 Gateway 접근·CORS·쿠키 전달은 별도 검증한다.
- 로그인 응답, 본인인증 요청·응답, 배송지 등록 필수 필드, 찜 페이지 응답 구조는 YAML에 반영됐다. 이를 통째로 재질문하지 않고 [코드 대조와 화면 연동의 빈칸](./API_CONTRACT.md#46-코드-대조와-화면-연동의-빈칸)만 확인한다.
- 최신 YAML의 찜 삭제는 200이고 대조 코드·기존 테스트는 204다. 가입 nickname은 YAML에 없고 코드에서는 필수다. 소셜 로그인·가입·연결은 코드에 있으나 YAML에 없다. 어느 쪽도 임의로 확정하지 않고 BE에 이번 연동 범위를 확인한다.
- ErrorResponse.detail의 배열/null 설명과 object 스키마를 일치시켜야 한다. 가입 address의 자유 객체 정의·응답 required/null·가입/갱신 Set-Cookie 누락도 보완 대상이다.
- 이메일 찾기·비밀번호 재설정은 #217에서 BE develop `d7ea517` 코드와 대조하고 FE를 연결했다([현재 계약](./API_CONTRACT.md#47-로그인계정-복구-코드-대조-217)). 메일 발송기 실연동과 운영 재설정 URL·PortOne 콜백 설정을 확인한다. 로그아웃은 `POST /api/v1/auth/logout`으로 확정돼 #254에서 연결했다([세션 종료](./AUTH_DESIGN.md#세션-종료-254)). 로그아웃 진입점은 원본 `2000:44497`(FL_B_MY_HOME)로 확정해 마이페이지에 연결했다. 로그아웃 후 이동 목적지는 원본에 프로토타입 연결이 없어 화면 접근 조건으로 정했다([세션 종료](./AUTH_DESIGN.md#세션-종료-254)).

- 요구사항 정의서는 LIVE 공급자를 “000 기반”으로 표현하므로 Amazon IVS로 확정하지 않는다.
- 휴대폰 본인인증은 포트원 SDK 결과의 identityVerificationId를 서버 검증 API로 전달한다. 200·인증 헤더 불필요·30분 일회성 토큰 및 회원가입 실패 분기는 [API 계약 초안](./API_CONTRACT.md)에 반영했다. 실제 호출 환경과 결과 불명 시 복구는 추가 확인한다.
- 판매자 등록 흐름은 별도 화면 명세가 없어 현재 라우트를 만들지 않았다.
- 프로젝트 상세의 `live-proof` 탭 노출은 LIVE 진행 여부를 서버에서 확인해야 한다.
- 환불·취소·배송조회 CTA는 FE 시간 계산이 아니라 서버 eligibility와 불가 사유를 따른다.
- `.env.example`에는 계약이 확정된 변수 이름만 추가한다.
- 판매자 프로젝트 편집 사이드바의 "기본 정보 수정" 탭은 `docs/ROUTING.md`의 `tab` 허용값에 없어 비활성 항목으로 뒀다. 값이 정해지면 라우팅·사이드바를 같이 갱신한다.
- 스토리 작성 에디터의 이미지·동영상 삽입은 업로드 API가 없어 base64로 콘텐츠에 직접 임베드한다. 파일 업로드 결정(P1) 전까지의 임시 조치이고, 결정 후 실제 업로드로 교체한다.
- BE의 introContent는 TEXT/IMAGE/VIDEO_URL 순서 배열이며 업로드 완료 URL을 저장한다. 에디터 HTML·base64 목업의 변환 규칙과 TEXT 서식 표현은 협의가 필요하다.
- 프로젝트 약관 코드·필수 구분과 카테고리별 disclosure 필수 키는 함께 정한다. Member 회원가입 약관과 프로젝트 개인정보 동의를 같은 계약으로 합치지 않는다.
- 최종 계약과 변경 기준은 Swagger다. 문서 갱신 책임·공유 채널·구버전 유지 기간은 협의하고, MSW는 합의한 임시 명세 범위에서 먼저 작성할 수 있다.
