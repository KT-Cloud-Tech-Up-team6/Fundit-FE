## 자동 검사

Lighthouse 13.5.0과 macOS Google Chrome(154)으로 접근성 범주만 측정했다. 모바일은 Lighthouse 기본 모바일 에뮬레이션, 데스크톱은 `--preset=desktop`을 사용했다. 공개 5개 화면은 `--headless=new`로, 판매자 목록은 로그인 상태를 유지하는 일반(헤드풀) Chrome 프로필로 측정했다. 원본 JSON은 로컬 검사 자료로 별도 보관하며 저장소에는 포함하지 않는다.

2차 재검증에서 공개 화면 5개와 판매자 목록은 모바일·데스크톱 모두 90점 이상이다. 이 결과는 자동 검사 점수일 뿐, 아래의 위반이 없다는 뜻은 아니다.

판매자 목록은 QA 전용 판매자 계정으로 로그인한 별도 Chrome 프로필에 디버깅 포트로 Lighthouse를 붙이고 `--disable-storage-reset`을 사용해 인증 상태를 유지한 채 수집했다. 두 측정 모두 최종 URL이 `/seller/projects`로 유지돼 로그인 화면으로 리디렉션되지 않았다. 1차 때 데스크톱에서 인증이 풀렸던 문제가 이 방식으로 해소됐다. 목록에는 프로젝트 4개가 보였고 제목 계층은 `h1` → `h2` → `h3` 순서였다.

## 남은 위반

### 프로젝트 상세 비선택 탭의 색 대비

프로젝트 상세 `color-contrast` 위반이 모바일·데스크톱 모두 남아 96점이다. 선택되지 않은 탭 링크 4개(새소식, 커뮤니티, 서포터, 환불 정책)가 `text-text-disabled`(`#7a7c8a`)이고, 흰 배경에서 대비가 4.13:1이다. 본문 크기(16px)라 4.5:1이 필요하다. 소스 위치는 `src/features/buyer-project/ui/buyer-project-detail.tsx`의 탭 링크 `className`이다.

#512는 `--text-secondary`를 `charcoal-700`으로 올리고 placeholder 토큰을 새로 두었지만, `--text-disabled`는 비활성 요소의 대비 예외를 이유로 `charcoal-600`(`#7a7c8a`) 그대로 두었다. 이 탭은 클릭 가능한 링크인데 disabled 토큰을 써서 예외에 해당하지 않는다. #512 본문은 활성 텍스트에 `text-disabled`를 쓰는 곳(카드 판매자명, 모바일 하단 내비, 프로젝트 상세 탭 등)을 이 변경에서 다루지 않고, 연한 활성 텍스트용 토큰(`text_tertiary`) 협의 후 별도로 진행한다고 밝혔다. 따라서 이 위반은 누락이 아니라 디자인 토큰 협의를 기다리는 알려진 항목이다.

`text-text-disabled`는 이 파일 외에도 여러 화면에서 쓰이므로, 비활성이 아닌 텍스트에 쓰인 곳이 더 있을 수 있다. 이번에 측정하지 않은 화면은 확인하지 못했다.

이 감사의 범위는 수정을 포함하지 않는다. 이슈를 따로 만들지 않고 알려진 한계로 기록한다.

## 스크린리더 점검

macOS VoiceOver(한국어)를 켠 Chrome에서 점검했다. 1차에서 막혔던 OS 창 포커스 권한 문제는 Chrome 디버깅 연결로 DOM 포커스를 옮기는 방식으로 우회했고, VoiceOver가 읽은 문구는 AppleScript `last phrase`로 받았다. 이를 위해 VoiceOver 유틸리티에서 "AppleScript로 VoiceOver를 제어하는 것을 허용"을 켰다.

이 방식이 검증하는 것은 **Tab으로 포커스가 이동할 때 읽히는 문구**다. VoiceOver 커서(VO+방향키)나 로터로 정적 본문, 제목, 랜드마크를 훑는 점검은 하지 않았다. 아래 "읽힌 문구"는 실제 `last phrase` 값이다.

### 리워드 선택 (수정됨, #552)

- 리워드 선택 점검은 `demo-project`로 수행했다. 점검 시점에 홈에 노출된 프로젝트 12개 중 `demo-project`만 리워드가 있고 나머지는 "리워드 (0개)"였으므로, 실제 데이터로 검증한 결과가 아니다.
- "리워드 (5개)" 버튼은 "축소됨/확장됨"으로 상태를 읽는다. 괄호 안 숫자는 선택 수가 아니라 전체 리워드 수다.
- 리워드 항목은 일반 `button`이며 `aria-pressed`/`aria-checked` 등 상태가 없다. 이름에는 제목·가격·구성이 모두 포함된다.
- 항목을 선택하면 패널이 접히고 포커스가 "리워드" 버튼으로 돌아간다. VoiceOver는 "리워드 (5개) 축소됨 버튼"만 읽고, 선택된 항목과 합계는 음성으로 나오지 않았다. 합계는 `role="status"` 영역("총 1개 + 배송비 3,000원 222,000원")에 있지만 읽히지 않았다. 같은 방식의 `role="status"`인 공유 토스트는 읽혔으므로 라이브 영역 낭독 자체는 동작한다. 합계가 읽히지 않은 원인은 확정하지 못했다. 선택 직후 패널이 접히고 포커스가 이동하면서 낭독이 덮였을 가능성이 있다. 한 번의 점검이므로 재현성은 확인하지 못했다.
- 선택된 항목에는 "스탠다드 세트 삭제", "스탠다드 세트 수량 줄이기", "스탠다드 세트 수량 늘리기" 버튼이 붙고 이름이 명확하다.

## 수정 결과 (#547·#548)

2차에서 발견한 두 결함을 #551(로그인 포커스), #552(리워드 선택 안내)로 수정했다. 아래는 수정 후 **로컬 dev 서버(MSW 목 환경)와 macOS VoiceOver(Chrome 154)**로 확인한 결과이며, 수정이 반영된 배포본에서 다시 측정한 것은 아니다.

- #552는 선택 이벤트마다 갱신되는 `role="status"` 안내를 250ms 늦춰 포커스 낭독 뒤에 읽히게 했다. 같은 문구는 다시 읽히지 않아, 목록을 펼치거나 리워드를 지울 때 안내를 비우도록 했다. 이 마지막 변경은 브라우저에서 안내 영역의 변화로만 확인했고, 이후 VoiceOver 음성은 다시 측정하지 않았다.
- 리워드 선택은 목업 데이터(`demo-project`)로 확인했다. 점검 시점의 UUID 프로젝트는 리워드가 모두 0개였다. `demo-…` ID는 UUID가 아니어서 어떤 값이든 같은 목업 프로젝트를 보여 주는 데모 경로로 가며, 같은 `RewardSheet` 컴포넌트를 쓴다.
- #551은 응답이 늦는 일반 오류에서도 비밀번호로 포커스가 돌아오고, 대기 중 폼 밖("아이디 찾기")으로 옮긴 포커스는 건드리지 않는 것을 확인했다.

## 조작을 막는 문제

점검한 흐름에서 키보드나 VoiceOver로 작업을 완료하지 못하게 하는 문제는 발견하지 않았다.

## 미수행 항목

- 리워드가 실제로 등록된 UUID 프로젝트에서의 선택·수량 조작 점검 (배포 프로젝트의 리워드가 모두 0개라 목업으로 대신 확인)
- #547·#548 수정이 반영된 배포본에서의 Lighthouse·VoiceOver 재측정
- 모달 Escape와 포커스 복귀 (찜·공유·알림·설정·내 계정을 눌러 보았으나 모달이 열리지 않았다. 결제·주문·마이페이지 등 다른 화면은 점검하지 않았다)
- VoiceOver 커서·로터 기반 정적 콘텐츠 탐색
- 모바일 VoiceOver(iOS)
- 2차 재검증 시점의 실제 배포 이미지 태그 확인

## 판정

공개 5개 화면과 판매자 프로젝트 목록의 Lighthouse 접근성 점수는 모바일·데스크톱 모두 90점 이상이다(가장 낮은 프로젝트 상세도 96점). #475~#478로 보고된 위반은 프로젝트 상세의 탭 대비 1건을 제외하고 해소됐고, 키보드·VoiceOver 점검에서 발견한 결함 두 가지는 #551, #552로 수정했다. 점검한 흐름에서 작업을 막는 문제는 없었다.

이 감사는 아래 한계를 둔 채 완료로 판정한다.

- 프로젝트 상세 비선택 탭의 색 대비(4.13:1)는 연한 활성 텍스트용 토큰(`text_tertiary`)에 대한 디자인 협의를 기다리는 알려진 항목이라 이번에 수정하지 않았다.
- #547·#548의 수정 확인은 로컬 빌드에서 했고, 수정이 반영된 배포본에서의 재측정은 하지 않았다.
- 위 "미수행 항목"의 범위는 점검하지 않았다.
