# 구매자 LIVE 시청·채팅 디자인

## 실제 라이브 연동 범위 (#227)

- AI 팀 라이브 테스트 요청에 따라 실제 UUID 방송의 영상 재생과 구매자 Q&A를 BE 공개 계약에 연결한다. 계약 원본·경로·응답 필드는 [API_CONTRACT.md 5.6](./API_CONTRACT.md#56-라이브-플레이어ai-qa-227)을 따른다.
- 아래 디자인 구현 이력과 목업 동작은 명시적인 데모 방송·Storybook에 대한 설명이다. 실제 UUID 방송에서 예시 상품·질문·답변·시청자 수를 실제 데이터로 표시하지 않는다.
- 구매자와 판매자 모니터링의 플레이어는 같은 재생 컴포넌트를 사용한다. 영상 조회·재생 오류와 Q&A 조회 오류는 서로 독립적으로 처리한다. 다시보기가 준비되지 않은 409 응답은 미준비 상태로 안내한다.
- 구매자 Q&A에는 서버의 질문 건수·답변 본문·답변 주체를 사용한다. 실시간 채팅 송수신, 큐시트·하이라이트 생성, 방송 시작·종료 변경은 이번 작업 범위 밖이다.
- 테스트 HLS·모의 API 검증은 실제 IVS·BE·AI 통합 검증을 대신하지 않는다. 실제 테스트 환경의 배포와 방송 준비 여부는 별도로 확인한다.
- #227 검증(2026-09-21): 격리 Playwright에서 390×844·1440×1000의 Q&A 로딩·응답·빈 목록·503 재시도, 재생 404/409·VOD·영상 오류 재시도, URL 이동·뒤로 가기와 기존 데모를 확인했다. 판매자 원문·초안·수정 답변 등록, 403/503·등록 실패·비로그인 처리도 모의 API로 확인했으며, 테스트 HLS의 실제 재생 시간 증가를 검증했다. 실제 IVS·BE·AI 환경과 Safari 네이티브 HLS는 별도 검증 대상이다.

## 구현 경계

- `/live/[liveId]`를 `(buyer-live)` 그룹에 두고 전용 헤더를 표시한다. 구매자 공통 헤더·하단 메뉴를 중복 표시하지 않는다. 다른 구매자 페이지는 변경하지 않는다.
- `?mode=replay`는 별도 다시보기 와이어프레임을 표시한다. 범위와 숏 클립은 [BUYER_LIVE_REPLAY.md](./BUYER_LIVE_REPLAY.md)를 참고한다. 실시간 구현은 변경하지 않는다.
- 기존 `DialogBase`, 닫기·전송·펀딩 아이콘을 재사용한다. 시청자 아이콘은 메인 작업과 같은 `buyer-live/viewers.svg`를 사용한다. 일치하는 기존 자산이 없는 아이콘만 Figma SVG로 추가한다.
- Figma 방송·상품·판매자 이미지를 기존 로컬 에셋에서 재사용하고 데이터는 `model/room-demo.ts`에 분리한다. 방송 이미지는 포스터이며 IVS 재생이 아니다.
- 공용 Button·Avatar·Icon·DialogBase를 재사용한다. InputChat은 금칙어 강조 미러를 지원하지 않아 기존 입력 구현을 유지한다.
- 신규 이미지 배치는 Tailwind를 사용하고, 기존 CSS Module은 뷰포트 높이·입력 미러·Q&A 드래그와 상태 선택자에 사용한다. 회색 표현은 semantic 토큰으로 교체한다. 방송 위 글자는 static white이며, Figma의 검정 50% 그라데이션·80% 안내 배경·텍스트 그림자는 대응 토큰이 없어 원본 alpha를 유지한다. 금칙어 강조는 공통 `--text-warning`을 사용한다.
- 실제 송출·채팅 서버·인증 가드·AI 질문 요약·서버 금칙어 검증·영구 저장은 포함하지 않는다.

## 목업 동작

- 채팅 영역을 누르면 높이 156px와 280px를 전환한다. 메시지 로그는 별도 `role="log"`로 읽을 수 있으며 새 메시지를 polite 방식으로 알린다. 키보드 포커스 시 나타나는 별도 버튼으로도 확대·축소한다. 메시지 입력에 포커스하면 156px로 축소한다.
- 입력은 최대 3줄 높이까지 늘어나며 이후 내부 스크롤한다. Enter 또는 전송 버튼으로 보내고 Shift+Enter는 줄바꿈한다. IME 조합 중 Enter는 전송하지 않는다.
- Figma 예시인 `바보`만 강조하고 전송을 차단한다. 실제 금칙어 목록·판정 정책으로 사용하지 않는다. 수정 후 정상 메시지는 로컬 채팅에 추가한다.
- Q&A는 원본처럼 고정 예시 5개를 표시한다. 제목을 포함한 상단 여백을 위/아래로 끌면 높이가 따라 움직이며, 놓으면 축소·확대 상태로 정렬된다. 제목 클릭·키보드로도 전환한다. 확대 시 헤더 아래 12px를 남긴다. 제목은 고정하고 목록만 스크롤하며 스크롤바는 숨긴다. Esc·바깥 영역·키보드 접근용 닫기 버튼으로 닫고 기존 Q&A 버튼으로 포커스를 복원한다.
- 팔로우·좋아요는 현재 화면 안에서만 토글한다. 새로고침·화면 이탈·다른 liveId 진입 시 초기화한다.
- 공유는 현재 라이브 URL을 클립보드에 복사한다. 전체 화면은 브라우저 Fullscreen API를 사용하며 지원하지 않으면 안내한다. 나가기는 `/live`로 이동한다.
- 일반 안내는 4초 후 사라진다. 같은 안내를 다시 요청해도 표시 시간을 갱신하며, 입력 변경·화면 이탈 시 타이머를 정리한다. 금칙어 오류는 수정할 때까지 유지한다. Storybook NoticeDismiss에서 안내 자동 해제를 확인한다.
- 알려진 목업 방송은 model/live-demo.ts의 명시적 관계를 app에서 전달받는다. 제품 카드 본문은 프로젝트 상세로 이동하고, `5+ 더보기`는 사용자가 확인한 동작대로 기존 리워드 선택 시트를 연다. app에서 두 기능을 조합하며 최신 결제 지시문 1132:15072에 따라 리워드 누적 선택·수량을 주문서로 전달한다. 상품명·판매자·대표 이미지를 유지한다. 관계가 없는 ID는 기존 미연결 안내를 유지한다. 실제 API 식별자 관계·로그인 가드·결제 연동은 별도 작업이다.
- 카드 가격 219,000원·199,000원과 `5+` 표시는 디자인 목업이다. 선택값과 수량은 주문서에 전달하며 실제 주문 저장·청구는 별도 API 연동 작업이다.
- 시청자·펀딩 수치, 판매자, 상품, 질문과 답변은 Figma 예시이며 실제 집계나 서버 데이터가 아니다.

## 검증

- Storybook play에서 팔로우·좋아요 토글, 채팅 높이, Q&A 확대·닫기·포커스, IME 전송 방지, 정상 전송, 차단 후 재입력을 검증한다.
- Chromium에서 좁은 화면과 뷰포트 높이 변화, 가로 넘침, 드래그, 기존 경로를 확인한다. 실제 모바일 OS 키보드·iOS Fullscreen 지원 여부는 실기기 검증이 별도로 필요하다.

- 별도 breakpoint 문구는 없어 사용자 승인에 따라 기존 구매자 데스크톱과 같은 1200px 기준을 사용한다. 1200px 콘텐츠에 384px 3열·24px 간격, 높이 726px 정보·우측 패널과 725px 영상으로 배치한다. 짧은 창에서는 페이지 스크롤을 허용하며 리워드·채팅·Q&A는 내부에서 스크롤한다.
- app의 LiveViewport가 현재 폭에 해당하는 화면 하나만 마운트한다. 모바일 컴포넌트의 기존 레이아웃·동작은 유지하며 분기점을 넘나들면 해당 화면의 일시 상태는 초기화한다. 실시간·다시보기·숏 클립 및 방송 ID를 변경할 때도 상태를 분리한다.
- 공통 구매자 헤더의 나가기는 `/live`로 연결한다. 리워드 5개는 기존 designRewards와 같은 데이터이며 직접 선택하지 않는 정보 목록이다. 상세 정보 보기는 app에서 전달한 목업 관계의 프로젝트로 이동한다. 관계가 없는 방송은 상세 버튼을 비활성화한다. 실제 상품 데이터 연결을 의미하지 않는다.
