# 판매자 펀딩 AI 스토리 목업

- AI 스토리 서버 적용 성공 시 해당 사용자·프로젝트의 미리보기 캐시를 함께 갱신합니다. 이전 조회는 먼저 취소하여 늦게 도착한 결과가 적용 내용을 덮어쓰지 않도록 하며, 실패 시 기존 캐시를 유지합니다.

## 진입과 구현 범위

`/seller/projects/demo-story?tab=story`에서 펀딩 스토리 AI 버튼을 선택합니다. 제품 설명 → 추가 질문 3개 → 요약·수정 요청 → 생성 → 결과 → 본문 불러오기를 제공합니다. 실제 AI 호출 없이 로컬 목업 상태를 사용합니다.

질문은 `storyQuestions`를 단일 원본으로 사용합니다. 최신 화면에도 동일 질문 반복과 일부 진행 숫자 오류가 남아 있어 기존 질문 구성과 배열 기반 분모를 유지합니다. 해당 사항 없음은 답변과 사용자 메시지로 기록됩니다. 이전 질문의 버튼도 대화에 남지만 비활성화하여 중복 답변을 막습니다. 수정 요청은 요약과 결과에 추가하는 목업이며 자연어로 기존 답변을 자동 교정하지 않습니다.

공용 `Modal`, `ChatDialogue`, `InputChat`, `Chip`, `Button`, `TextButton`을 재사용합니다. 채팅의 `appearance="story"` 옵션으로 기존 기본 스타일을 유지하면서 최신 AI 흰색·사용자 검정 말풍선과 14px 본문을 적용합니다. 아바타와 로딩 로고는 지정 Figma 노드에서 직접 내보낸 SVG입니다.

대화·생성 모달은 588×672px, 결과 모달은 996×672px이며 작은 화면에서는 뷰포트에 맞게 축소합니다. 입력창과 44px 전송 버튼은 분리됩니다. 입력 높이는 28px에서 최대 160px까지 확장하고 이후 내부 스크롤을 사용합니다. 테두리·패딩 포함 최대 입력 영역 높이는 178px입니다. Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 전송 방지를 제공합니다. 전송하면 입력 높이는 28px로 초기화됩니다. 이전 대화를 읽는 동안 자동 하단 이동을 중단하고, 하단 복귀 또는 새 메시지 전송 시 다시 따라갑니다.

생성 화면은 원본 로고의 위치·회전과 전환 시간을 CSS로 반영했습니다. SLOW의 내부 스프링 계수와 별도 키프레임은 도구에서 제공되지 않아 easing은 CSS ease-out 근사입니다. 양방향의 정확한 스프링 궤적 일치는 미검증입니다. 모션 감소 설정에서는 애니메이션을 중단합니다. 원본의 큐시트 오기는 기존 사용자 승인에 따라 스토리로 표시합니다.

결과 모달은 본문만 스크롤하고 헤더·하단 버튼을 유지합니다. 이전으로는 답변을 보존한 요약 화면, 재생성은 같은 입력의 새 목업 결과로 이어집니다. 불러오기는 현재 Tiptap 소개 본문을 교체하며 이후 작성 화면에서 편집하고 상세페이지 미리보기로 확인할 수 있습니다. 실제 저장·게시를 수행하지 않습니다.

## 상태와 연동 경계

- 프로젝트 식별자와 탭은 URL이 소유합니다. 프로젝트 변경 시 작성 폼의 `key={projectId}`로 편집 상태가 초기화됩니다.
- 대화와 생성 단계는 기능 내부 reducer가 소유합니다. 모달을 닫으면 대화는 초기화되고, 불러온 본문은 현재 편집기에 남습니다. 새로고침이나 화면 이탈 시 로컬 내용은 초기화됩니다.
- 지연 타이머는 상태 변경·모달 닫기 때 해제합니다. `pauseDemo`는 Storybook의 정지된 생성·요약 상태 검사용입니다.
- 결과 내부 원본은 HTML 링크 들어갈 자리라는 자리표시자입니다. 현재는 입력 내용을 React로 렌더링한 목업 결과를 사용합니다. 실제 HTML 응답·구조화 본문·Tiptap 변환 계약은 미확정이며 외부 HTML을 실행하지 않습니다.
- 첨부 아이콘은 표시하되 파일 종류·제한·업로드 계약 확인 전까지 비활성화합니다.
- 생성·조회·반영 API 초안은 [API_CONTRACT.md](./API_CONTRACT.md#55-ai-스토리)에 있습니다. 질문 제출·오류·재시도·폴링·결과 변환 계약 및 실제 연동은 남아 있습니다.
- IA의 재생성 입력 초기화·복사하기와 현재 목업의 차이는 이 디자인 작업에서 변경하지 않습니다. 별도 제목 수정·임시저장·저장도 기존 비활성을 유지합니다.

## 검증

#167에서 최신 원본의 시작·입력·질문·답변·요약·생성·결과 12개 화면과 지시 `1406:38778`, 히스토리 `1260:35258`을 다시 대조했습니다. 추가 코드 변경 없이 상태 모델 4개와 관련 Storybook 28개 시나리오가 통과했습니다. 실제 작성 URL에서 한글 조합 중 Enter 방지, 해당 사항 없음의 사용자 발화·지난 질문 비활성, 요약 수정·이전으로·재생성의 답변 보존, 본문 불러오기·미리보기·메뉴 이동 후 뒤로가기를 재검증했습니다. 입력 최대 160px, 과거 대화 읽기 유지·전송 후 하단 복귀와 모달 재열기 초기화도 확인했습니다. 실제 AI·첨부 API와 정확한 스프링 궤적은 위 연동 경계를 유지하며, #165 공통 반응형 변경을 합친 검증은 별도입니다.

상태 모델 테스트는 `pnpm test src/features/funding-ai-story/model/story-demo.test.mjs`로 실행합니다. Storybook의 Funding AI Story 및 공용 ChatDialogue·InputChat 시나리오로 입력 높이·전송·지난 질문 비활성·결과 CTA·컴포넌트 호환성을 검사합니다. 실제 작성 페이지의 AI 불러오기 → Tiptap 편집 → 상세페이지 미리보기 흐름은 독립 Playwright headless 프로덕션 브라우저로 검증합니다.

2026-09-18 검증에서 모델 테스트 4개, 관련 Storybook 27개 시나리오, format·lint·typecheck와 Next.js·Storybook 빌드가 통과했습니다. 실제 페이지의 한글 조합·질문 건너뛰기·요약 수정·이전으로·재생성·불러오기·상세페이지 미리보기·메뉴 이동·뒤로가기를 확인했습니다. 320·390px 대화·결과 모달의 가로 넘침과 버튼 접근, 모션 감소 설정도 확인했습니다. 마지막 입력창 보완은 프로덕션 빌드와 별도 브라우저 검사로 320px 안내 문구 높이 40px, 390·1440px 높이 28px, 최대 입력 높이 160px, 이전 대화 스크롤 유지·전송 후 하단 이동·포커스 복귀를 검증했습니다. Storybook의 기존 번들 크기 및 플러그인 처리 시간 경고는 남아 있습니다.

# API 연동 현황 (#193)

- 서버 UUID 프로젝트의 스토리는 소유자 미리보기로 조회하고 PATCH story로 저장합니다. 제목·표지 이미지·일반 텍스트·이미지·영상 블록을 복원합니다.
- 파일은 서명 URL PUT 성공 후에만 삽입합니다. 실패하면 기존 본문을 유지합니다. 실제 S3·Gateway 검증은 환경 안내 대기입니다.
- 굵게·색상·정렬·인용·이미지 그룹 등 서버 블록으로 보존할 수 없는 서식이나 중간 빈 문단은 저장 오류로 안내합니다. 임의로 서식을 제거하지 않습니다.
- AI 대화 입력은 상품 설명으로 묶어 BE 목업 세션 생성·조회에 전달합니다. 실제 AI 연동은 제외합니다. 현재 동기 COMPLETED 응답을 지원하며 비동기 폴링·추가 질문 계약은 추후 연동 대상입니다.
- 불러오기는 OVERWRITE를 명시해 서버 스토리에 적용합니다. 이미지가 포함된 AI 결과는 손실 방지를 위해 적용을 막습니다. 미리보기의 제목·썸네일·본문 외 상품 정보는 기존 예시임을 표시합니다.
- 기존 데모 ID와 Storybook은 아래 목업 동작을 유지합니다. 전체 서식·AI 비동기 흐름이 미완료이므로 이슈를 자동 종료하지 않습니다.

## 스토리 미디어 저장 경계

서버 프로젝트의 미디어 업로드는 공통 `uploadProjectMedia`에서 MIME·확장자·용량을 검사한다. 에디터가 삽입 종류를 업로드 콜백에 전달하며 본문 이미지와 썸네일은 `image`로 JPG·PNG·WebP 10MB 이하, 본문 영상은 `video`로 MP4 100MB 이하만 허용한다. 파일 선택창 필터를 우회해도 이미지에 MP4, 영상에 이미지가 삽입되지 않는다. 에디터는 업로드 검증 실패의 원인을 표시하고 기존 콘텐츠를 유지한다.

서버에서 불러온 프로젝트는 임시저장·저장을 동일한 소개 저장 API로 처리한다. API 데이터가 없는 데모는 미리보기만 제공한다.
