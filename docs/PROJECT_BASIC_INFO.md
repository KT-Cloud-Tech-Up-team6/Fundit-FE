# 판매자 기본 정보·리워드 목업

## 리워드 API 연결 (#192)

- 신규 리워드 생성 결과가 불확실하면 같은 탭 세션에서 해당 사용자·프로젝트의 추가 생성을 차단합니다. 네트워크·5xx·파싱 실패 후 단순 재시도로 중복 생성하지 않으며, 다른 기기·탭까지 보장하려면 BE 멱등성 계약이 필요합니다.

- 서버 UUID 프로젝트의 `?tab=rewards` 및 기본정보 화면에서 판매자 리워드 조회·등록·수정·삭제를 사용합니다. #191 기본정보 저장과 함께 사용할 수 있으며 저장 요청은 분리합니다.
- 프로젝트 ID는 UUID, 리워드 ID는 BE가 반환한 숫자입니다. 이미지 업로드는 서명 URL PUT 성공 후에만 저장합니다.
- 실패 시 입력을 유지하고 성공 응답을 캐시에 반영한 뒤 목록을 다시 조회합니다. 배송 필드는 수정 요청에서 생략해 기존 서버 값을 보존합니다.
- BE PR #108 계약에 따라 옵션 그룹·값을 편집합니다. 기존 `groupId`는 PATCH의 `optionGroupId`로 유지하고 신규 그룹은 ID 없이 전송합니다. 옵션을 건드리지 않으면 `options`를 생략하고, 옵션 설정을 해제하면 `options: []`를 전송합니다. 값은 전체 교체됩니다.
- 생성·수정 응답의 영속화된 그룹 ID를 재편집에 사용합니다. 쓰기 응답의 옵션 값 `valueId`는 null일 수 있으며 구매자 주문용 옵션 ID로 사용하지 않습니다.
- 배송 정보 입력·환불정책 편집은 미완료입니다. `simpleRefundDisabled`는 읽기 전용입니다. 아래 목업 설명은 데모 ID와 Storybook에 해당합니다.
- 옵션 수정·추가·삭제·전체 해제·응답 ID 재사용·실패 시 입력 보존을 격리 브라우저의 API fixture로 확인했습니다. 실제 BE/S3 연동은 별도 검증이 필요합니다.

## API 연동 현황 (#191)

- 실제 생성 화면은 #97 인증 기반으로 프로젝트 생성 후 기본정보를 PATCH합니다. 목록 카드의 이동 경로는 #324 이후 [ROUTING.md](./ROUTING.md#내-프로젝트-목록-이동-경로-324)를 따릅니다(프로젝트명은 스토리 작성, 관리 버튼은 펀딩 관리).
- 기본정보 저장과 리워드 저장은 분리합니다. 서버 UUID가 있는 프로젝트는 리워드 API를 사용하며 기본정보 저장에 리워드를 포함하지 않습니다. 신규 생성 전의 데모 리워드는 서버에 저장하지 않습니다. 프로젝트 공개도 호출하지 않습니다.
- 5종 동의 모달의 필수 조건은 유지합니다. BE 프로젝트 동의 `agreed`와 의미가 달라 해당 API는 호출하지 않으며 동의 영구 저장 계약은 BE 확인 대기입니다.
- 제목은 40자 이하, 목표 금액은 기존 화면 기준 500,000원 이상의 안전한 정수입니다. 임시저장은 입력한 필드만 전송합니다.
- 소유자 미리보기 API로 제목·목표금액·카테고리·사업자 유형을 복원합니다. 같은 세션의 저장 응답이 있으면 우선하며, 사업자 유형 미선택 시 PATCH에서 제외해 기존 값을 유지합니다.
- 카테고리는 [Issue #212](https://github.com/KT-Cloud-Tech-Up-team6/Fundit-FE/issues/212)의 A안으로 PRD 4.2.4·BE `V14__seed_categories_confirmed.sql`의 7개 대분류·38개 조합을 `project-categories.ts`에 유지합니다. 대분류·소분류 모두 한글명을 전송하고 잘못된 조합은 전송 전에 차단합니다. `INVALID_CATEGORY` 응답이면 다시 선택하도록 안내합니다. search-service 시드가 동기화되지 않아 카테고리 조회 API는 사용하지 않으며 구매자 목업 목록은 별도로 유지합니다.
- 생성 요청 전에 사용자별 sessionStorage에 시도 상태를 기록합니다. 생성 성공 후 PATCH 실패 시 새로고침·재진입해도 같은 서버 ID를 사용합니다. 네트워크·5xx·응답 파싱 실패로 생성 여부가 불확실하면 추가 생성을 차단하고 준비중 목록에서 확인하도록 안내합니다. 같은 탭 세션에 적용되는 FE 보호이며, 여러 탭·기기 및 안전한 재생성 복구는 BE 멱등성 계약이 필요합니다.
- #267에서 신규 생성의 첫(임시저장 아닌) 저장 성공 시 완료 모달 `1958:44217`을 추가했습니다. `다음에`는 방금 만든 프로젝트의 `?tab=basic-info`, `펀딩 스토리 작성`은 `?tab=story`로 이동합니다. 기존처럼 저장 즉시 리다이렉트하지 않고 모달 버튼 클릭까지 새 프로젝트 id를 들고 있습니다. 임시저장과 기존 프로젝트 수정 저장에는 노출하지 않습니다.
- 실제 BE·PortOne 연결 검증은 Gateway 및 테스트 환경 안내 대기입니다. 테스트 응답을 이용한 FE 검증과 실제 서버 검증을 구분합니다.

### 기본 정보·리워드

- 사업자 유형, 제목, 카테고리, 목표 금액 입력과 금액 증액·초기화.
- 리워드 빈 상태, 추가, 목록, 수정, 삭제.
- 작성 중 하단 저장은 리워드를 현재 목록에 반영합니다. 작성 패널이 닫혀 있으면 기본 정보의 목업 입력을 검사합니다.
- 수량 제한을 해제하면 저장 시 수량을 비웁니다. 얼리버드·옵션은 승인된 범위에 따라 체크 상태만 유지하며 상세 설정 패널은 만들지 않습니다.
- Storybook 목업의 임시저장·저장은 서버나 브라우저 저장소를 사용하지 않습니다. 실제 화면은 기본정보와 서버 UUID 프로젝트의 리워드를 각각 API로 저장합니다. 데모 리워드 목업은 새로고침·이동 시 초기화됩니다.
- 데모 이미지 선택은 파일 이름만 목업 상태에 반영합니다. 서버 UUID 프로젝트의 리워드는 검증 후 서명 URL로 업로드합니다.
- 상세 카테고리는 실제 폼과 Storybook 모두 프로젝트 저장용 7개 대분류·38개 확정 조합을 제공합니다.
- 목표 금액 500,000원, 리워드 이름·양의 정수 가격·제한 수량 검사는 화면 목업용이며 BE 계약을 확정하지 않습니다.

## 리워드 API 업로드 검증

리워드 이미지는 JPG·PNG·WebP, 10MB 이하만 허용한다. MIME·확장자·빈 파일·용량을 업로드 URL 요청 전에 검사하고, 서버의 `UNSUPPORTED_MEDIA_TYPE`·`MEDIA_TOO_LARGE` 거절도 형식·용량 안내로 표시한다. 프로젝트 미디어 공통 업로더가 검증을 소유한다.

생성 결과가 불명확한 리워드 시도의 잠금은 목록 재조회만으로 해제하지 않는다. 목록 부재는 진행 중인 생성 요청의 실패를 증명하지 않는다. 안전한 해제에는 BE의 생성 멱등성 키와 결과 조회 계약이 필요하며, 현재 보호는 같은 탭 범위다.
