## 구현 범위

- `/search`를 전용 `(buyer-search)` 그룹에 두며 기존 BuyerShell에 영향을 주지 않는다.
- `q`, `tab=projects|live|sellers`, `status=live|upcoming`, `sort=latest|popular|closing`, `closed=true`를 URL로 관리한다. 브라우저 뒤로가기·앞으로가기로 제출된 검색 조건을 복원한다.
- 한글 조합 중 Enter는 검색을 제출하지 않는다. 검색어 삭제 시 초기 화면으로 돌아간다.
- 최근 검색어 중복 제거·삭제, 정렬·필터, 유형별 결과, 팔로우·알림 토글은 목업 동작이다. 최근 검색어·팔로우·알림은 현재 검색 화면에서만 유지하며 영구 저장이나 다른 화면 동기화는 하지 않는다.
- 프로젝트·진행 중 LIVE는 기존 상세 경로로 연결한다. 예정 LIVE는 알림 신청을 제공하며 판매자 프로필 목적지는 미정이라 링크를 만들지 않는다.
- 실제 검색·추천·랭킹·알림 API와 로그인 가드는 포함하지 않는다. 목업 금액·일정·인기순은 예시 데이터다.
- OS 키보드·상태 표시줄·홈 인디케이터는 직접 그리지 않는다. 모바일 390px 디자인을 기준으로 작은 화면에 맞추고 데스크톱은 중앙 정렬한다.
- Tailwind의 공통 색상·타이포그래피 토큰을 사용하며 화면에서 전역 색상 변수를 재정의하지 않는다. 와이어프레임의 검정·회색보다 프로젝트의 라이트·다크 테마 토큰을 우선한다.
- `SearchField`, `TabList`, `Tab`, `Checkbox`, 보조 버튼 클래스와 판매자 행을 재사용한다. `ProjectRow`는 관심 목록에서도 사용하며 썸네일 너비와 찜 버튼은 각 화면에서 전달한다. 작은 정렬 컨트롤은 박스형 공통 Select와 형태가 달라 native select를 유지한다.
- 공통 토큰에 없는 프로젝트·LIVE 제목의 14px/20px/500 조합과 작은 보조 컨트롤의 글자 크기는 로컬 예외로 유지한다. 전역 토큰을 추가하거나 기존 타이포그래피 토큰의 굵기·줄높이를 덮어쓰지 않는다.

## 검증

- Storybook `Features/BuyerSearch`의 7개 상태와 SearchFlow.
- EmptySubmission에서 기존 검색어를 모두 지우거나 공백만 제출하면 `q`가 비워지고 초기 화면으로 돌아가는지 검증한다.
- `pnpm test src/features/buyer-search/model/search-demo.test.mjs`.
- 실제 `/search`에서 URL 직접 진입·뒤로가기 및 한글 입력, 정렬·필터와 빈 결과를 확인한다.
- Composition 스토리는 입력·조합 이벤트를 명시적으로 전달해 조합 중 제출 차단과 조합 종료 후 제출을 검증한다. 브라우저 자동화의 Enter 명령이 키 이벤트를 전달하지 않아 실제 OS 한글 키보드 조합은 별도 확인이 필요하다.
