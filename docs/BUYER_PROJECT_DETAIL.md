# 구매자 프로젝트 상세 디자인

## API 연결 범위 (#195)

- 진행 중(ONGOING) 프로젝트의 펀딩 버튼은 공통 FundingCta를 사용합니다. 실제 UUID 주문 흐름은 PR #206과 함께 검증·반영해야 하며, 종료·준비중 프로젝트에서는 참여 버튼을 비활성화합니다.

- `/search`는 BE 검색 API의 정렬, 종료 필터, 페이지를 URL로 유지한다. 카테고리 소분류는 #307부터 LIVE 홈으로 이동해 카테고리 API를 쓰지 않는다. 검색 초기 화면의 프로젝트는 홈 인기 피드이며 개인화 추천이 아니다.
- `/projects/{UUID}`는 공개 상세·리워드·환불정책·공지 목록·커뮤니티·LIVE 검증 정보와 LIVE 체크 탭의 종료된 라이브·숏 클립 목록(#319)을 조회한다. 기존 `demo-project`는 디자인 확인용 경로다.
- `/search`와 `/projects/{UUID}`의 새소식·커뮤니티 탭은 `page`가 마지막 페이지보다 뒤면 [이전 페이지]가 응답 `totalPages`의 마지막 페이지(0건이면 첫 페이지)로 간다(#374, `shared/lib/previous-page.ts`).
- 목록 응답의 프로젝트 ID는 Long이고 상세 요청은 UUID다. 매핑 계약이 없어 목록의 상세 이동을 비활성화했다. 표시 코드나 숫자를 UUID로 변환하지 않는다.
- 공지 본문, 메이커·서포터 정보, 실제 영상, 찜과 결제 승인은 이 변경에 포함하지 않는다. 서버가 제공하지 않는 통계·AI 요약을 목업 값으로 채우지 않는다.
- 비로그인 세션 확인 완료 후 공개 조회를 시작한다. 실패 시 오류·재시도를 제공하며 목업 성공으로 대체하지 않는다.
- 390px·1200px 독립 headless 브라우저에서 테스트 응답으로 검색·페이지 이동·뒤로가기·실패 재시도·카테고리 이동·UUID 상세·새로고침을 검증했다. 실제 Gateway 환경과 BE 통신은 미검증이다.

## LIVE 체크 탭 LIVE 다시 보기 (#319)

- `/projects/{UUID}?tab=live-proof`는 Figma LIVE 체크(`1541:50459`)처럼 "LIVE 다시 보기"(`1541:50492`) 아래에 LIVE Q&A를 보인다. 목록 모양(가로 스크롤·드래그, 카드 크기)은 데모와 같은 `VideoList`를 쓴다.
- 종료된 라이브는 `GET /api/v1/lives?status=ENDED&projectId=`의 첫 페이지(20건, 생성 최신순)다. 카드는 LIVE 썸네일·소개 문구(없으면 "소개 문구 없음")·실제 방송 시작일(`actualStartAt`, 한국 시간 MM.DD)이고, 누르면 `/live/{liveId}?mode=replay`로 간다. 종료된 라이브는 항상 공개다(2026-09-23 PM).
- 숏 클립은 `GET /api/v1/lives/highlights?projectId=`의 첫 페이지(20건)다. 판매자가 LIVE 클립 관리에서 공개한 완료 클립만 오고, 목록 조회는 쇼츠 조회 수를 올리지 않는다. 카드는 썸네일(없으면 클립 영상의 첫 프레임)·배지(DEMO는 "시연 영상", 그 밖은 "하이라이트", #317)·제목(없으면 "숏 클립")·생성일이고, 누르면 `/live/{liveId}?mode=replay&view=clip&clip={highlightId}` 쇼츠로 간다.
- 건수는 서버 전체 건수(`totalElements`)다. 목록마다 불러오는 중·오류(다시 시도)·빈 목록("종료된 라이브가 없습니다.", "공개된 숏 클립이 없습니다.")을 따로 보이고, 건수를 모를 때는 적지 않는다. 원본에 상태가 없어 FE가 정했다(노션 FE 자체 판단).
- IA 소비자 26행의 "LIVE 방송을 진행한 프로젝트만 탭 노출"은 아직 반영하지 않았다. LIVE 체크 탭은 모든 프로젝트에 보인다.

## 실제 프로젝트 리워드 선택 (#368)

- 진행 중인 `/projects/{UUID}`도 데모와 같은 Figma 리워드 선택(`FL_B_PY_RWRD_1~7` `1867:48973`~`1867:49809`, 웹 `2107:70345`·`1541:50148`, 지시 `1441:72101`)을 쓴다. 1200px 이상은 오른쪽 인라인 폼과 펀딩하기 제출 버튼, 그보다 좁은 화면은 펀딩하기로 여는 바텀시트다. 예전 체크박스 선택 모달은 제거했다.
- `GET /api/v1/projects/{id}/rewards` 응답을 `toRewards`(`reward-selection/model/public-reward.ts`)로 시트 모델에 옮긴다. 상세와 주문서는 `public-rewards` 키 하나로 조회 캐시를 나눠 쓴다. 리워드를 받기 전·조회 실패·종료 프로젝트는 기존 리워드 요약(불러오는 중·재시도)을 두고 펀딩하기를 비활성화한다.
- 카드 배지는 선착순 한정 → 얼리 버드(정률은 "얼리 버드 N%", 정액은 "얼리 버드") 순이다. 가격은 얼리 버드 할인가, 정가는 취소선이다. 메타 줄은 리워드 설명만 적고, 배송비·예상 발송일은 카드에 두지 않는다(2026-09-28 노션 PM-3 회신). 혜택 칩·구성품 줄은 응답에 없어 두지 않는다. 품절 리워드는 드롭다운에서 비활성화하고 "품절"을 적는다.
- 판매자 리워드 등록에 배송비·발송 소요일 입력 칸이 없어 BE `shippingFee`·`estimatedDeliveryDays`는 항상 비어 있다(PM-3 (나) 답변: 입력 칸 추가 안 함). FE는 이 필드들을 읽지 않는다. 배송비는 리워드별이 아니라 주문 1건당 3,000원 고정값(`reward-demo.ts`의 `SHIPPING_FEE`)이며, 리워드 선택 시트의 합계와 목업 주문서 결제 요약에서만 "+ 배송비 3,000원"으로 안내한다.
- 옵션 그룹마다 선택 상자를 두고 모든 그룹을 고르면 그 조합을 줄로 담는다. 그룹이 여럿이면 값을 " / "로 잇는다. 같은 조합은 수량을 더하고 다른 조합은 별도 줄이다. 남은 재고(`remainingStock`)는 같은 리워드 모든 줄 수량 합의 상한이며, 다 담으면 옵션 선택 상자를 막는다.
- 선택 카드 금액과 합계는 화면 단가(얼리 버드 할인가)로 계산하고, 주문서는 기존처럼 서버 미리보기 금액을 쓴다. BE #181(요청서 BE-22, PM-2 "할인가로 청구")부터 BE 주문 금액도 얼리 버드 할인가로 계산해 둘이 같다. 배송비는 BE가 3,000원 고정으로 계산하므로, 선택 시트 합계도 담은 리워드가 있을 때 같은 3,000원을 한 번만 더해 주문서 금액과 어긋나지 않게 한다(2026-09-28 사용자 결정).
- 펀딩하기는 담은 줄을 `{rewardId, quantity, optionValueIds}[]`로 바꿔 기존 실제 주문서 `/funding/{UUID}/checkout?items=`로 이동한다. 로그인 확인은 주문서의 회원 게이트가 맡고, 로그인 뒤 선택이 담긴 같은 주소로 돌아온다. 데모 프로젝트는 메모리 세션 흐름을 그대로 쓴다.
- 주문서는 상세에서 담은 줄을 옵션까지 그대로 보여 주고 주문하며, 주문서에서 리워드를 고치지 않는다. 예전 "리워드 변경" 체크박스 모달은 리워드마다 한 줄을 전제로 해 같은 리워드의 옵션 줄을 함께 바꿨고, 원본(Figma 주문서 `FL_B_PY_ORD_1` `1534:54000`, IA `FL_B_PY_ORD`)에도 없어 #373에서 없앴다. 리워드는 상세의 리워드 선택에서만 고른다. 주문서의 줄 검증(`order-checkout/model/order-lines.ts`)은 상세와 같이 같은 리워드 줄들의 수량 합을 남은 재고와 비교한다(#378).

## 실제 주문서 (#382)

- 실제(UUID) 주문서 `OrderCheckoutApi`와 데모 주문서 `OrderCheckoutScreen`은 같은 Figma 주문서(`FL_B_PY_ORD_1` `1534:54000`) 조각 `checkout-parts.tsx`(모바일 상단 바·1200px 이상 오른쪽 sticky 상자 배치, 결제 금액, `price_information`)와 `ShippingAddressSection`·`ShippingAddressSheet`를 함께 쓴다. 데모는 목업 값과 메모리 세션, 실제는 API 조회 값과 주문 생성으로 채운다.
- 결제 수단(신용/체크카드·카드사·할부)과 적립금은 실제 주문서에 두지 않는다(노션 FE 자체 판단 79, 적립금은 IA 33행 취소선·PM 구현 제외). 결제 버튼은 주문(`POST /api/v1/orders`)을 만든 뒤 `/payment/{orderId}`로 교체 이동하고, 결제 수단은 그 화면의 Toss 결제위젯에서 고른다. 결제 버튼 위에 "결제 수단은 다음 화면에서 선택합니다."를 적는다.
- 결제 금액은 BE 주문 미리보기(`POST /api/v1/orders/preview`) 값과 주문 줄의 정가로 만든다(판단 80, #429). BE #181부터 `rewardAmount`는 얼리 버드 할인가 합계라, Figma처럼 ㄴ펀딩 금액은 줄 정가 합계, ㄴ얼리버드 할인은 정가 합계 − `rewardAmount`, ㄴ쿠폰 사용은 `discountAmount`, 총 할인 금액은 둘의 합, 총 주문 금액은 펀딩 금액 + `shippingFee`, 최종 결제 금액은 다시 계산하지 않고 `finalAmount`다. 얼리 버드가 없으면 ㄴ얼리버드 할인은 0원 줄로 둔다(Figma의 0원 줄과 같다). 줄 청구 금액 합계가 `rewardAmount`와 다르면(BE #181 이전 BE의 정가 청구, 리워드 조회와 미리보기 사이의 가격 변경) 가격 차이를 할인으로 추정하지 않는다. 이때 ㄴ펀딩 금액은 `rewardAmount`, ㄴ얼리버드 할인은 0원이고 주문 상품 줄도 정가("상품 금액")로 보인다. 주문서에 들어오면 리워드를 다시 조회한다. 미리보기 전(리워드 확인 전·배송지 없음·조회 중·실패)은 안내나 재시도를 두고, 버튼은 "결제하기"다. 미리보기가 오면 "N원 결제"(`finalAmount`)가 된다.
- 주문 상품은 프로젝트 썸네일(`coverImageUrl`, 없으면 빈 칸)·제목을 한 번 두고, 넘겨받은 줄마다 "리워드명 · 옵션 · N개"와 줄 금액을 둔다(판단 81). 예상 발송일은 두지 않는다(2026-09-28 노션 PM-3 회신). 옵션 값과 줄 금액은 리워드 선택과 같은 `toRewards` 모델로 만든다. 옵션 그룹이 여럿이면 " / "로 잇는다. 줄 금액은 청구 단가 × 수량이다. BE #181부터 얼리 버드는 할인가로 청구하므로 Figma `price_information`대로 정가 취소선·"얼리버드 할인"·할인가를 두고, 얼리 버드가 아니면 "상품 금액"을 둔다(#429).
- 배송지는 저장 배송지 중 기본 배송지(없으면 첫 배송지)로 시작한다. "배송지 변경"은 저장 배송지 목록 시트(`SavedAddressSheet`)를 열고 누르면 바로 적용한다. 목록의 "신규 배송지"와 저장 배송지가 없을 때의 "신규 배송지"는 배송지 입력 시트를 연다. 입력한 주소는 이 주문에만 쓰고 저장하지 않는다. 저장 배송지가 없으면 섹션 머리에 회원 이름·연락처를 둔다(Figma "배송지 없을 때"). 목록 조회가 실패해도 재시도와 함께 새 주소 입력은 열어 둔다.
- 결제 버튼은 Figma 히스토리 `1534:54171`대로 늘 누를 수 있다. 누르면 주문할 수 없는 줄·쿠폰 오류가 있을 때 주문 상품으로, 배송지가 없을 때 "* 배송지를 입력해주세요" 경고와 함께 배송지로, 금액 확인 전이면 결제 금액으로 스크롤하고, 그 밖에는 주문을 만든다. 쿠폰 적용도 배송지가 없으면 같은 경고를 띄운다. 주문 생성 중에는 버튼을 막고 "주문 생성 중"으로 바꾸며, 실패 안내 옆에 참여 내역 링크를 둔다.
- 선택 없는 주문서 안내, 주문할 수 없는 줄 안내, 회원 게이트(`returnTo`), 쿠폰 선택 시트(`CouponApiSheet`)와 쿠폰 거절 안내, 주문 중복 생성 방지(`submitOrderOnce`)는 그대로다. 데모 주문서의 동작(목업 금액·적립금·결제 수단·데모 완료)은 바뀌지 않았다.

## 구현 범위

- 전용 헤더, Figma 상품·방송 이미지, 판매자·펀딩 정보, AI 요약, 가로 탭, 상품 소개 이미지, LIVE 콘텐츠 목록, 찜·펀딩 하단 버튼을 구현한다.
- 원본 SVG와 상품 소개 이미지를 사용한다. 동일한 공유·찜·질문 아이콘과 기존 리워드 선택 시트를 재사용한다.
- 찜은 로컬 상태다. 공유는 현재 프로젝트 탭 URL을 복사한다. 안내 버튼은 클릭으로 열고 Escape 또는 포커스 이탈로 닫는다.
- 안내 툴팁은 primary 배경·inverse 글자·왼쪽 꼬리·11px Medium·한 문단을 적용한다. 작은 화면에서는 화면 안에 들어오도록 너비를 줄인다. Storybook LiveInformationTip에서 LIVE Q&A 안내도 확인한다.
- 두 탭 모두 원본의 `9999+` 축약 표시를 유지하며 찜 버튼은 로컬 상태로 토글한다.
