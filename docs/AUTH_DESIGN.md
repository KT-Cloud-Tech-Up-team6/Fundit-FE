## 적용 원칙

실제 UI, 문구, 상태, 인터랙션은 첫 번째 회원가입 Figma를 단일 기준으로 삼는다. 로그인 반응형 예시는 시각 디자인이나 문구를 가져오는 원본이 아니라, 넓은 화면에서의 콘텐츠 배치 원칙만 참고한다.

| 화면 크기       | 적용 방식                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------- |
| 모바일          | 회원가입 Figma의 390px 화면을 기준으로 구현한다. 좌우 20px 여백 안에서 콘텐츠 폭은 350px이다. |
| 태블릿·데스크톱 | 인증 폼의 폭을 넓히지 않고 350px으로 유지해 화면 가운데에 배치한다.                           |
| 좁은 화면       | 폼 폭은 `min(350px, 100vw - 40px)`로 제한해 좌우 20px 여백을 보장한다.                        |

Figma 회원가입 프레임을 실측하면 상태바를 제외한 웹 콘텐츠 기준으로 헤더는 52px이고,
헤더가 있는 폼의 본문은 화면 상단에서 136px(헤더 52px + 여백 84px)에 시작한다.
가입 방식처럼 헤더가 없는 화면은 화면 상단에서 128px에 시작한다. 844px보다 낮은 화면에서도
이 상단 정렬을 유지하고, CTA는 문서 흐름 안에 두어 콘텐츠와 함께 스크롤되게 한다.

```css
.auth-content {
  width: min(350px, calc(100vw - 40px));
  margin-inline: auto;
  padding-top: 84px; /* 52px 웹 헤더 아래, 화면 상단 기준 y=136px */
}

.auth-content--without-header {
  padding-top: 128px;
}
```

## 회원가입 화면 범위

Figma `1007:9253`은 하나의 정적 화면이 아니라 아래 회원가입 플로우와 상태를 포함한다.

1. 로그인/가입 진입: FundIt 로고, 카카오·구글·이메일 로그인, 회원가입 링크
2. 약관 동의: 약관 목록 바텀시트, 항목 선택, 약관 상세 보기
3. 소셜 로그인: 외부 OAuth 완료 후 약관 동의, 이후 온보딩 이동
4. 일반 가입 및 본인인증: 디자인의 본인정보 입력 → PortOne 통합인증 → 서버 결과 검증 → 회원정보 입력
5. 상태 처리: 인증창 요청·취소·실패, 서버 검증 중·실패·완료, 입력 오류와 토스트 안내

입력과 회원가입 CTA는 기본적으로 52px 높이이며, 모바일 폼의 주요 콘텐츠 폭은 350px이다. 글꼴은 Pretendard 계열을 사용한다. 로그인 폼(`FL_C_ME_LOGIN_2`)의 "로그인" 버튼만 46px로, 회원가입 CTA와 의도적으로 다르다.

## 향후 API 연동 범위

화면 구현 후 아래 단위로 실제 API 계약과 연결한다. 상세 요청·응답 및 인증 정책은 [API 계약 초안](./API_CONTRACT.md), 미확정 사항은 [OPEN_DECISIONS.md](./OPEN_DECISIONS.md)를 따른다.

- 카카오·구글 OAuth 시작, 콜백 및 세션 복구
- 이메일 로그인 및 가입 처리
- 약관 목록 조회, 필수/선택 동의 저장, 약관 상세 조회
- PortOne SDK 본인인증 요청 및 결과 수신
- 본인인증 결과 서버 검증 및 가입 완료 처리

## 확정 정책

- 본인인증의 검증 주체는 자체 SMS API가 아니라 PortOne 통합인증이다. 디자인에서 먼저 받은 이름·전화번호 등은 PortOne 요청과 최종 가입 요청에 사용한다.
- 닉네임은 필수이며 최대 50자로 제한한다.
- 비밀번호는 백엔드 기준인 8자 이상, 대문자·소문자·숫자·특수문자 중 3종 이상을 적용한다. 비밀번호 확인은 프론트에서만 검증한다.
- 가입 성공 시 발급된 세션을 유지하고 관심 카테고리 선택 화면을 거쳐 홈으로 이동한다.
- 로그인과 가입 성공 후 Refresh Cookie를 이용한 자동 로그인을 기본으로 사용한다.
- 아이디 저장은 이메일만 브라우저 로컬 저장소에 보관하며 비밀번호와 인증 토큰은 저장하지 않는다.
- 약관 목록과 전문은 `GET /api/v1/terms`를 사용한다. AI 개인화 안내와 툴팁 문구는 별도 API 필드가 생기기 전까지 프론트 문구로 관리한다.
