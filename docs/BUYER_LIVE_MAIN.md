## 변경 사항

- Figma 원본 상품·판매자 이미지를 `public/images/buyer-live`에 저장하고 UI 목업을 `model/live-demo.ts`로 분리한다. API 응답 DTO나 실시간 데이터가 아니다.
- 신규 오픈은 정사각형, 실시간 순위·팔로우·추천 카드는 3:4 비율, 예정 카드의 시간은 이미지 위 딤으로 표시한다. 예정 탭 추천 카드는 1200px 미만에서 원본대로 정사각형이다.
- 일반 제목은 2줄, 실시간 순위와 예정 목록 제목은 3줄로 제한한다. 알림 신청 수는 한 줄에서 말줄임한다.
- 콘텐츠 상단 16px, 섹션 사이 40px, 순위 목록 사이 16px, 콘텐츠 하단 40px를 적용한다.
- 예정 화면에 팔로우 판매자 캐러셀, 날짜별 예정 목록, 알림 신청 목록, 추천 라이브를 추가한다.
- 디자인의 카드 날짜 `09.18`은 목업 카드에서 원본 그대로 표시한다. 날짜별 예정 제목(Figma `9/8일 (화)`)은 실제 페이지에서 탭을 연 날의 한국 날짜와 요일로 쓴다(예: `9/29일 (화) 예정된 라이브`, 2026-09-29 사용자 결정, #432). Storybook처럼 탭을 연 시각을 넘기지 않으면 원본 문구 그대로다.
- 추천 목록은 기존 동작대로 10개씩 추가하고 30개에서 종료한다. Figma의 추천 예시 8개를 반복하며 각 카드 ID는 구분한다. 키보드용 더 불러오기 버튼을 제공한다.
- 예정 목록의 `100,00명` 표기는 기존 숫자 목업 100,000명을 유지한다. 예정 팔로우 네 번째 카드의 이미지·상품 문구 불일치는 Figma 원문 그대로 유지한다.

## 구현 경계

- 두 메인 경로만 `(buyer-live)` 그룹에서 RootLayout을 공유한다. 기존 BuyerShell 및 다른 구매자 페이지는 변경하지 않는다.
- 공용 BuyerBottomNavigation, SearchField, 링크형 Tab/TabList, Button, Badge, Avatar, Icon을 재사용한다.
- 스타일은 Tailwind와 semantic 토큰을 기본으로 사용한다. CSS Module은 포커스·스크롤바 선택자, Badge 내부 토큰, LIVE 화면 전용 내비게이션 표현에 한정한다. 기존 회색 전역 토큰 덮어쓰기는 제거한다.
- 디자인의 static LIVE 파랑은 기존 `text-primary-live` 및 Badge 내부의 blue 토큰에 매핑하며 전역 토큰은 수정하지 않는다. 내비게이션의 채움 LIVE 아이콘은 Figma SVG이며, 이 화면 안에서만 공용 아이콘의 inline mask를 재정의한다. PC 헤더는 두 탭(`/live`로 시작하는 경로)에서 라이브 메뉴만 채움 아이콘(파랑)과 기본 글자색으로 활성이다(`1419:51918`, #527).
- 팔로우 여부는 `hasFollowing`으로 표현하며 false이면 해당 섹션을 숨긴다.
- 시작 알림은 React 상태만 변경하며 새로고침·페이지 이탈 시 초기화한다. 알림 신청 목록도 같은 상태를 사용한다.
- 검색·전체보기·알림함은 기존 경로를 유지한다. 예정 탭의 팔로우·일정·알림 신청·추천 카드는 명시적인 목업 관계를 통해 프로젝트 상세로 이동한다. 상품명·판매자·대표 이미지를 상세에 전달한다. 예정 목록의 더 보기 목적지는 미정이므로 비활성으로 유지한다. 목업 ID를 실제 API 식별자로 사용하지 않는다.
- 주석 1055:14788은 알고리즘 기반 추천 사유 뱃지를 요구한다. 현재 사유 뱃지는 목업이며 실제 추천 순서·사유 계산은 서버 연동 대기다. 신규·순위·팔로우·LIVE 검색의 별도 화면은 사용자 결정에 따라 placeholder로 보류한다.
- 카테고리는 기존 카테고리 화면과 복귀 동작을 유지한다. IVS 재생·추천 알고리즘·실제 알림·영구 저장은 포함하지 않는다. 실제 LIVE는 아래 #345 절의 칸에만 섞는다.

## 검증

- Storybook play에서 팔로우 표시 여부, 알림 토글과 다른 카드 상태 보존, 검색 입력/지우기, 링크 경로, 표시 배지 클릭을 확인한다.
- 브라우저에서 390px·320px·데스크톱의 가로 넘침, 두 탭 이동, 추천 목록 추가와 종료를 확인한다.
- SubscriptionKeyboard는 목록에서 해제 후 다음·이전 버튼과 빈 목록으로의 포커스 이동을 검증한다. RecommendationKeyboard는 추가된 첫 카드로의 포커스 이동과 30개 종료 안내를 검증한다.

- #114: 신규 오픈·예정 팔로우 목록은 공용 `useHorizontalDrag`로 데스크톱 마우스 드래그를 지원하며 스크롤바는 항상 숨긴다. 6px 이상 움직인 드래그 뒤의 클릭은 막고 일반 클릭·키보드·모바일 네이티브 스크롤은 유지한다. 세로 휠을 가로 이동으로 강제 변환하지 않는다.

- #116: 마지막 목록 아래 40px는 흰색 콘텐츠 영역에 포함한다. 하단 메뉴는 Figma의 88px에서 OS 홈 인디케이터 34px를 제외한 54px에 실제 safe area를 더하며, 페이지도 같은 높이를 예약한다.

## 실제 LIVE 섞기 #345

- 목업 데이터는 BE 시더(BE #154, PR #165)가 채우기로 해(2026-09-29 사용자 결정·PM 요청, #432) 섹션의 **모든 칸을 실제 LIVE로 앞에서부터 API 순서대로 채우고, 실제 LIVE가 모자라는 뒤쪽 칸만 목업**으로 둔다. 09-24 PM 방식(섹션마다 일부 칸만 실제 LIVE)은 이것으로 바뀌었다. 칸 수는 모바일·데스크톱에 보이는 칸을 모두 센다(신규 오픈·예정 팔로우 6칸 중 모바일 4칸, 실시간 순위 10위 중 모바일 5위, 날짜별 예정 8칸 중 모바일 5칸, 실시간 팔로우 4칸). 섞는 규칙은 `model/live-main-real.ts`의 `fillRealSlots`와 단위 테스트가 맡는다. 조회 계약은 [API_CONTRACT.md](./API_CONTRACT.md) 5.10이다.
- 목업 LIVE와 스튜디오에서 만든 실제 방송을 가리는 규칙은 두지 않는다(응답에 구분 값이 없고 썸네일 유무로 가르지 않는다, 2026-09-29 사용자 결정). 새로 만든 실제 LIVE는 최신순인 신규 오픈의 첫 칸에 오지만, 실시간 순위는 시청자 수 순이라 IVS가 stub인 동안 BE 목업의 시청자 수(09-29 dev 211~271명)보다 적으면 밀려 보이지 않을 수 있다.
- 섹션별 후보는 다음과 같다. 맞는 LIVE가 없거나 조회가 실패하면 그 섹션은 목업만 보이고 오류 안내는 없다.
  - 신규 오픈: `GET /lives`(최신순)에서 `LIVE`·`SCHEDULED`만 고른 앞 6개. 목록 응답에는 시청자 수가 없어, 같은 화면이 받은 실시간 순위 조회(첫 페이지)에 같은 LIVE가 있으면 그 `viewerCount`를 목업 카드와 같은 시청자 뱃지로 보인다. 순위에 없으면 숫자 대신 LIVE 뱃지, 예정이면 "예정됨" 뱃지를 쓴다.
  - 실시간 순위: `GET /lives?status=LIVE&sort=viewerCount`의 1~10위. 순위 번호는 칸 위치이고 시청자 수는 `viewerCount`다.
    - 4위는 시연 칸이다(PM 2026-09-29, #445). 시연 제품인 Figma 목업 카드 "[진짜싹싹] 35,000Pa 초강력 흡입, 가볍게 끝내는 무선청소기"(`rank-4`, 테크·가전, 10,900%, 홈메이트랩)를 늘 그대로 보이고(다른 목업 순위 카드는 모바일에서 Figma대로 10,000%지만 이 카드는 모바일도 10,900%, 2026-09-29 사용자 결정), 실제 LIVE는 1~~3위와 5~~10위를 채운다(`fillRankingSlots`).
    - 4위 카드를 누르면 가장 최근에 만든 방송 중 LIVE(`/live/{liveId}`)로 간다(2026-09-29 사용자 결정). 시연 때 만들어 시작한 방송이 가장 최근 LIVE라 그 방송으로 들어간다. 방송 중 LIVE를 최신순으로 받는 `GET /lives?status=LIVE`의 첫 항목이다. 신규 오픈의 전체 상태 목록에서 고르면 그 뒤에 예정·종료 LIVE가 20건 넘게 생겼을 때 놓쳐서 따로 받는다(#447 리뷰). 방송 중인 LIVE가 없으면 목업 화면(`/live/rank-4`)이다. 시연 전에는 가장 최근의 BE 목업 방송으로 가고, 시연 방송 뒤에 다른 LIVE를 만들어 시작하면 그쪽으로 간다. 4위가 가리키는 LIVE가 순위에 섞여 오면 다른 칸에서 뺀다.
    - 실제 카드의 제목·카테고리·달성률은 LIVE 목록에 없어 보이는 칸의 프로젝트 상세(`GET /projects/{projectId}`)의 `title`·`categoryMajor`·`fundingStatus.achievementRate`를 쓴다(#445, 2026-09-29 사용자 결정). Figma 순위 카드의 제목이 프로젝트명이고, 시드의 소개 문구("{상품}, 지금 라이브에서 자세히 만나보세요.")를 제목으로 쓰면 어색해서다. 달성률은 PM이 준 목업 값을 BE 시더가 넣은 것이고, 상세 화면과 같은 쿼리 키라 카드와 상세의 값이 같다. 받기 전과 실패한 카드는 제목을 소개 문구로 두고 카테고리·달성률은 비운다.
  - 팔로우한 창작자: 팔로우 목록 앞 100명의 `sellerId`를 붙여 실시간 탭은 `status=LIVE`의 앞 4개, 예정 탭은 `status=SCHEDULED`를 날짜별 예정과 같이 화면을 연 시각 이후 `scheduledStartAt` 오름차순으로 다시 세운 앞 6개. BE는 예정 시각이 지나도 판매자가 시작하기 전까지 `SCHEDULED`로 두므로 지난 예정은 뺀다.
  - 날짜별 예정: `GET /lives?status=SCHEDULED` 첫 페이지(20건)를 화면을 연 시각 이후의 `scheduledStartAt` 오름차순으로 다시 세운 앞 8개. 제목의 날짜는 탭을 연 날이고, 목록은 그 시각 이후의 예정을 날짜와 관계없이 이른 순서로 보인다(#432).
- 실제 카드의 판매자는 소비자 LIVE 목록의 `sellerNickname`(BE PR #165)이고, 없으면 판매자 줄을 그리지 않는다(#427). 순위 카드의 판매자 아바타는 기본 이미지다. 순위 카드의 카테고리·달성률은 위처럼 프로젝트 상세에서 받고, 그 밖의 카드의 카테고리와 알림 신청 수는 BE에 없어 비운다. 제목은 `introText`이고(실시간 순위 카드는 위처럼 프로젝트명) 비어 있으면 "소개 문구 없음"이다. 썸네일이 없으면 카드의 중립 배경만 남는다. 외부 썸네일 주소는 최적화 없이 그대로 쓴다. 예정 카드의 날짜·시간은 한국 시간이다.
- 방송 중 카드는 `/live/{liveId}`로 간다. 예정 카드는 재생 정보가 없어 목업 예정 카드(`getUpcomingProjectHref`)처럼 실제 `projectId`의 프로젝트 상세(`/projects/{projectId}?tab=story`)로 간다.
- 실제 예정 카드의 알림 버튼은 목업과 같은 화면 상태만 바꾼다. 실제 알림 API가 없어(IA 알림함 제외) 알림 신청한 라이브 목록에는 목업 카드만 보인다.
- 팔로우 여부는 로그인 회원의 팔로우 목록 전체(`follow-api.ts`의 `followsQueryKey`, LIVE 시청 화면과 같은 키)로 판단한다. 비로그인·팔로우 0명·조회 실패면 두 탭의 팔로우 섹션을 숨긴다(Figma 주석 `1408:42072`). 팔로우는 있지만 맞는 방송이 없으면 목업만으로 보인다.
- 조회는 실제 페이지 전용 `BuyerLiveMainApi`가 하고 `BuyerLiveMain`은 `real`로 받은 값만 그린다. Storybook은 `real` 없이 그려 전부 목업이다.
- 실제 LIVE 응답이 오기 전에는 목업 칸이 먼저 보였다가 실제 카드로 바뀐다.
