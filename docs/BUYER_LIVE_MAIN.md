## 확인 경로

- 앱 `/live`, `/live/upcoming`.
- Storybook `Features/BuyerLive/Main`의 Default, NoFollowing, NotificationToggle, SearchAndNavigation, UpcomingNoFollowing.
- 1200px 미만은 기존 390px 모바일 원본 기준으로 중앙 정렬하고, 1200px 이상은 아래 데스크톱 원본을 적용한다.
- 기기 상태바·홈 인디케이터는 복제하지 않으며 하단 메뉴에 safe area를 적용한다.

## 변경 사항

- Figma 원본 상품·판매자 이미지를 `public/images/buyer-live`에 저장하고 UI 목업을 `model/live-demo.ts`로 분리한다. API 응답 DTO나 실시간 데이터가 아니다.
- 신규 오픈은 정사각형, 실시간 순위·팔로우·추천 카드는 3:4 비율, 예정 카드의 시간은 이미지 위 딤으로 표시한다.
- 일반 제목은 2줄, 실시간 순위와 예정 목록 제목은 3줄로 제한한다. 알림 신청 수는 한 줄에서 말줄임한다.
- 콘텐츠 상단 16px, 섹션 사이 40px, 순위 목록 사이 16px, 콘텐츠 하단 40px를 적용한다.
- 예정 화면에 팔로우 판매자 캐러셀, 날짜별 예정 목록, 알림 신청 목록, 추천 라이브를 추가한다.
- 디자인의 날짜 제목 `9/8일 (화)`와 카드 날짜 `09.18`은 원본 그대로 표시한다. 원본의 불일치는 디자인 확인 사항이며 임의로 통일하지 않는다.
- 추천 목록은 기존 동작대로 10개씩 추가하고 30개에서 종료한다. Figma의 추천 예시 8개를 반복하며 각 카드 ID는 구분한다. 키보드용 더 불러오기 버튼을 제공한다.
- 예정 목록의 `100,00명` 표기는 기존 숫자 목업 100,000명을 유지한다. 예정 팔로우 네 번째 카드의 이미지·상품 문구 불일치는 Figma 원문 그대로 유지한다.

## 구현 경계

- 두 메인 경로만 `(buyer-live)` 그룹에서 RootLayout을 공유한다. 기존 BuyerShell 및 다른 구매자 페이지는 변경하지 않는다.
- 공용 BuyerBottomNavigation, SearchField, 링크형 Tab/TabList, Button, Badge, Avatar, Icon을 재사용한다.
- 스타일은 Tailwind와 semantic 토큰을 기본으로 사용한다. CSS Module은 포커스·스크롤바 선택자, Badge 내부 토큰, LIVE 화면 전용 내비게이션 표현에 한정한다. 기존 회색 전역 토큰 덮어쓰기는 제거한다.
- 디자인의 static LIVE 파랑은 기존 `text-primary-live` 및 Badge 내부의 blue 토큰에 매핑하며 전역 토큰은 수정하지 않는다. 내비게이션의 채움 LIVE 아이콘은 Figma SVG이며, 이 화면 안에서만 공용 아이콘의 inline mask를 재정의한다.
- 팔로우 여부는 `hasFollowing`으로 표현하며 false이면 해당 섹션을 숨긴다.
- 시작 알림은 React 상태만 변경하며 새로고침·페이지 이탈 시 초기화한다. 알림 신청 목록도 같은 상태를 사용한다.
- 검색·전체보기·알림함은 기존 경로를 유지한다. 예정 탭의 팔로우·일정·알림 신청·추천 카드는 명시적인 목업 관계를 통해 프로젝트 상세로 이동한다. 상품명·판매자·대표 이미지를 상세에 전달한다. 예정 목록의 더 보기 목적지는 미정이므로 비활성으로 유지한다. 목업 ID를 실제 API 식별자로 사용하지 않는다.
- 주석 1055:14788은 알고리즘 기반 추천 사유 뱃지를 요구한다. 현재 사유 뱃지는 목업이며 실제 추천 순서·사유 계산은 서버 연동 대기다. 신규·순위·팔로우·LIVE 검색의 별도 화면은 사용자 결정에 따라 placeholder로 보류한다.
- 카테고리는 기존 카테고리 화면과 복귀 동작을 유지한다. API·IVS 재생·추천 알고리즘·실제 알림·영구 저장은 포함하지 않는다.

## 검증

- Storybook play에서 팔로우 표시 여부, 알림 토글과 다른 카드 상태 보존, 검색 입력/지우기, 링크 경로, 표시 배지 클릭을 확인한다.
- 브라우저에서 390px·320px·데스크톱의 가로 넘침, 두 탭 이동, 추천 목록 추가와 종료를 확인한다.
- SubscriptionKeyboard는 목록에서 해제 후 다음·이전 버튼과 빈 목록으로의 포커스 이동을 검증한다. RecommendationKeyboard는 추가된 첫 카드로의 포커스 이동과 30개 종료 안내를 검증한다.

- #114: 신규 오픈·예정 팔로우 목록은 공용 `useHorizontalDrag`로 데스크톱 마우스 드래그를 지원하며 스크롤바는 항상 숨긴다. 6px 이상 움직인 드래그 뒤의 클릭은 막고 일반 클릭·키보드·모바일 네이티브 스크롤은 유지한다. 세로 휠을 가로 이동으로 강제 변환하지 않는다.

- #116: 마지막 목록 아래 40px는 흰색 콘텐츠 영역에 포함한다. 하단 메뉴는 Figma의 88px에서 OS 홈 인디케이터 34px를 제외한 54px에 실제 safe area를 더하며, 페이지도 같은 높이를 예약한다.

## 데스크톱 확장 #154

- [라이브 탭 & 상세페이지 섹션 `1419:48997`](https://www.figma.com/design/ifJ8lcDbezIb223WrS5m6d/?node-id=1419-48997)의 실시간 `1419:51899`, 예정 `1419:52381`을 적용한다. `1430:55901`의 1200px 이상 조건으로 공용 HeaderWeb 기반 구매자 헤더와 최대 1200px 콘텐츠를 표시한다.
- 작업 이력 `1419:51825`, 화면 정의 `1419:51889/51894`, 전체 섹션과 텍스트·박스 지시를 확인했다. 별도 interaction_spec·annotation·prototype reaction은 섹션 검사 결과 없고 인접 400px 영역에 별도 노트도 없었다.
- 신규 오픈과 팔로우 목록은 `1419:53382~53384`, `1419:53385~53387`의 가로 스크롤을 적용한다. 예정 화면은 데스크톱에서 일정→팔로우→알림 신청→추천 순서이고 모바일의 기존 순서는 유지한다.
- 데스크톱 순위 10개·예정 일정 8개는 기존 목업 상품을 반복 사용하며 순위·추천 알고리즘은 구현하지 않는다. 추천은 기존 10개씩 추가·최대 30개 정책이다. 데스크톱 추천은 5열, 알림 신청 목록은 3열이다.
- 신규 오픈·예정 팔로우 캐러셀의 데스크톱 5·6번째 카드는 기존 1·2번째 목업을 반복한다. 신규 오픈 원본 `1419:51921`도 같은 상품·이미지·판매자를 반복한다. 별도 상품이나 방송 데이터가 추가된 것은 아니며 각 카드의 목업 ID와 기존 상세 연결은 유지한다.
- 순위 달성률은 Figma 표시 예시다. 두 번째 카드 `1419:52015`의 실제 텍스트는 `120,000% 달성`이며, 5·6위와 8·9위의 달성률 역전도 원본에 존재한다. 달성률 내림차순이라는 정책은 정의되지 않아 임의로 정렬하거나 `12,000%`로 바꾸지 않는다. 실제 순위 산정은 API 연동 대기다.
- #171에서 최신 `1408:41424/41699`의 배지를 대조했다. 기존 시청자·알림·LIVE 아이콘을 중복 추가하지 않고, 모바일에도 LIVE 흰 글자와 시청자 파란 글자가 표시되도록 잘못된 색상 변수 참조를 수정했다. 상세의 LIVE 크기·색상은 #170, 모바일 D-28의 회색 S/웹 accent M 분기는 #171에서 반영했다. D-28은 공용 status-info 토큰(#e4e5e8)을 사용하며 Figma 표시값 #eeeef0와의 차이는 공용 토큰 변경 범위로 남긴다.
- 카테고리는 `/categories/tech-appliances`로 이동하며 기존 sessionStorage 복귀 경로를 기록한다. 헤더의 관심 목록·알림함·마이페이지·참여자 센터는 기존 구매자 경로를 사용한다.
- 기존 검색·전체보기 placeholder, 비활성 예정 더 보기와 API 미연동 범위는 유지한다. 이 문서의 기존 미연동 항목은 데스크톱 배치만으로 완료되지 않는다.
